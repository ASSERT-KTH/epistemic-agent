\section{Introduction}

Motivation:
\begin{itemize}
\item Interpretability at the action boundary: every consequence of an agent passes through a tool call, so that is where intent must be recorded.
\item Reasoning traces are verbose, often summarized, and increasingly hidden by providers; a typed reason costs a few hundred bytes per call.
\item Accountability in regulated domains (medical devices, avionics, automotive, infrastructure), which require knowing why each step was taken and what was tried and abandoned.
\item Machine-checkable policy: rules such as ``every \texttt{change-state} requires human approval'' can be enforced on types instead of by pattern-matching shell strings.
\end{itemize}


\section{Concept: The Epistemic Agent}

Every tool call carries three mandatory fields:
\begin{itemize}
\item \texttt{command}: the shell command to execute.
\item \texttt{type}: the kind of act, chosen from a closed vocabulary.
\item \texttt{reason}: free text stating the intent behind this specific call, not what the command does.
\end{itemize}

The vocabulary has seven act types \todo{shrink / expand}:
\begin{itemize}
\item \texttt{collect-info}: read-only observation to build understanding.
\item \texttt{test-hypothesis}: an experiment to confirm or refute a current belief; the reason names the belief and the observation that would refute it.
\item \texttt{change-state}: a persistent mutation that is part of the deliverable.
\item \texttt{verify}: re-running a known check on finished work; nothing is in doubt, the goal is evidence.
\item \texttt{setup}: preparing the environment (installs, scaffolding, fixtures); a means, not the deliverable.
\item \texttt{revert}: undoing a previous \texttt{change-state} that proved wrong, which makes dead ends explicit.
\item \texttt{cleanup}: removing temporary artifacts created by the agent.
\end{itemize}

Design principles:
\begin{itemize}
\item The type is declared before execution, so the agent commits to its epistemic situation before any side effect.
\item The type depends on the situation, not the command: \texttt{pytest} is \texttt{test-hypothesis} when a failure is expected and \texttt{verify} when confirming finished work.
\item File tools (read, write, edit) require a reason but no type, because their act type is fixed by the tool; asking for it would only invite inconsistency.
\item Calls are validated in-process: a missing or unknown type, or a reason that is too short, is rejected without execution and returned as a tool error for the model to fix.
\item Consistency checks tie type to command, e.g., \texttt{collect-info} must not redirect output, delete, commit, or install, and \texttt{revert} must refer to a prior \texttt{change-state}.
\end{itemize}

\subsection{Limitations}
\begin{itemize}
\item Reasons are declared, not evidenced: they are claims about intent and can be false.
\item Validation gates are shallow and do not stop a model that confabulates plausible reasons.
\item Each call pays a token overhead for the extra fields.
\end{itemize}

\section{Related Work}

\noindent\textbf{Intent integrity and guardrails.}
\begin{itemize}
% Securing LLM Agents Need Intent-to-Execution Integrity
\item Qu et al.~\cite{Qu2026SecuringLA} argue that agent security requires an end-to-end property stating when execution faithfully reflects the user's intent, by analogy with compiler correctness. Theirs is a position paper; we implement a harness that captures the agent's own intent at every tool call and evaluate it.
% Safeguarding LLM Agents from Misalignment through Provenance Analysis, ASE 2026
\item She et al.~\cite{She2026SafeguardingLA} present ProvenanceGuard, which blocks a proposed tool call unless it is supported by traceable evidence in the agent's context. They infer alignment with the user's intent from the context, whereas we require the agent to declare the type and reason of each act and make that declaration the object of verification.
% Enforcing Temporal Constraints for LLM Agents, boring rewriterule and temporal logic in the contextof coding agents
\item Kamath et al.~\cite{Kamath2025EnforcingTC} present Agent-C, which enforces formal temporal safety properties on sequences of tool calls via SMT solving and constrained generation. Their policies are expressed over raw tool calls; our closed act vocabulary gives a semantic layer on which such policies can be stated, such as forbidding a \texttt{change-state} without approval.
\end{itemize}

\noindent\textbf{Faithfulness of self-reports.}
\begin{itemize}
% Language Models Don't Always Say What They Think: Unfaithful Explanations in Chain-of-Thought Prompting
\item Turpin et al.~\cite{Turpin2023LanguageMD} show that chain-of-thought explanations can systematically misrepresent the true reason for a model's answer. In practice, default models largely verbalize their intent, but faithfulness is not guaranteed and degrades under pressure or optimization against monitors; our harness therefore treats declarations as trustworthy-by-default evidence and verifies the falsifiable part (the act type) against observed effects.
% Monitoring Reasoning Models for Misbehavior and the Risks of Promoting Obfuscation
\item Baker et al.~\cite{Baker2025MonitoringRM} show that a weaker LLM reading the chain of thought of a frontier reasoning model detects reward hacking in agentic coding far better than one reading actions alone, but that training against such a monitor yields obfuscated reasoning that hides the misbehavior. Their monitored signal is free-form reasoning; ours is a short, typed declaration whose act type can be checked against observed effects, so obfuscating the reason does not hide a false type.
% Spilling the Beans: Teaching LLMs to Self-Report Their Hidden Objectives
\item Li et al.~\cite{Li2025SpillingTB} fine-tune models to confess hidden objectives when interrogated after the fact. Our harness requires intent before each action rather than through post-hoc interrogation, and needs no fine-tuning.
\end{itemize}

\noindent\textbf{Monitoring agents for misbehavior.}
\begin{itemize}
% Reliable Weak-to-Strong Monitoring of LLM Agents
\item Kale et al.~\cite{Kale2025ReliableWM} red-team LLM monitors of agent trajectories and find that an agent aware of being monitored substantially degrades monitor reliability. Their monitors read unstructured trajectories; ours read typed, justified acts, which gives the monitor an explicit claim to check against the command.
% Constitutional Black-Box Monitoring for Scheming in LLM Agents
\item Storf et al.~\cite{Storf2026ConstitutionalBM} build black-box LLM monitors for scheming, optimized on synthetic trajectories and evaluated on ControlArena. They observe the agent from outside; we change the agent's interface so that every action carries a checkable statement of intent.
% AgentSight: System-Level Observability for AI Agents Using eBPF
\item Zheng et al.~\cite{zheng2025agentsight} present AgentSight, which observes agents from outside by correlating intercepted LLM traffic with kernel events via eBPF. It reconstructs intent after the fact, whereas our harness makes the agent declare the type and reason of each action before it executes.
\end{itemize}

\noindent\textbf{Deception, sabotage, and reward hacking.}
\begin{itemize}
% Are Your Agents Upward Deceivers?
\item Guo et al.~\cite{Guo2025AreYA} define agentic upward deception, where an agent hides failure and performs unrequested actions, and measure it on 200 tasks across 11 LLMs. Their benchmark measures the problem; our harness is a mitigation whose declared intents can be confronted with such deceptive actions.
% Coding with "Enemy": Can Human Developers Detect AI Agent Sabotage?
\item Ye et al.~\cite{Ye2026CodingW} find that 94\% of developers fail to detect sabotage by a coding agent, citing minimal review, plausible cover stories, and overtrust. The epistemic journal turns the cover story into an explicit, per-action artifact that can be checked automatically instead of by an overtrusting human.
% EvilGenie: A Reward Hacking Benchmark
\item Gabor et al.~\cite{Gabor2025EvilGenieAR} present EvilGenie, a benchmark where coding agents can reward hack by hardcoding tests or editing test files, and observe such behavior in Codex and Claude Code. We use this kind of cheating-prone setup to evaluate whether declared intents expose reward hacking.
\end{itemize}

\noindent\textbf{Provenance and audit trails.}
\begin{itemize}
% PROV-AGENT: Unified Provenance for Tracking AI Agent Interactions in Agentic Workflows
\item Souza et al.~\cite{Souza2025PROVAGENTUP} present PROV-AGENT, which extends W3C PROV to record prompts, responses, and decisions of agents in scientific workflows. It records what happened; our journal additionally records why each action was taken, in a closed vocabulary.
% From Agent Traces to Trust: A Survey of Evidence Tracing and Execution Provenance in LLM Agents
\item Wang et al.~\cite{Wang2026FromAT} survey evidence tracing and execution provenance for LLM agents, including whether tool calls were justified. Our harness is a concrete instance in which justification is mandatory at the action boundary.
\end{itemize}
