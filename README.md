# Epistemic agent

This repository contains the code and data for the paper
**"Episteme: Trustworthy Coding Agents Through Tool Call Intent"**.

A coding-agent harness that makes intent a mandatory part of every tool call. Before a shell command runs, the model
must declare what kind of act it is (a **type** from a closed vocabulary of seven) and why (a free-text **reason**).
The harness then records what the command actually did (the **effects**, from snapshots of the workspace before and
after the call), checks the declared type against those effects, and appends the declaration, the effects and any
findings to a journal that the agent cannot write.

The journal serves two uses:

- **Guardrail (online):** in `enforce` mode the harness refuses, before it runs, a call declared read-only whose
  command looks mutating.
- **Forensics (offline):** a reviewer, or the same checker run again on a stored journal, finds the calls whose
  effects contradict their declared type.

This repository holds the prototype, the experiments and the source of the accompanying paper, submitted to the IEEE
Software theme issue "Building Trustworthy Software in the Time of AI".

## The seven types

| Type | Meaning | Changes state? |
|---|---|---|
| `collect-info` | read-only observation to build understanding | no |
| `test-hypothesis` | an experiment to confirm or refute a stated belief | no |
| `verify` | re-running a known check on finished work | no |
| `change-state` | a lasting change that is part of the deliverable | yes |
| `setup` | preparing the environment (installs, scaffolding, fixtures) | yes |
| `revert` | undoing an earlier change that proved wrong | yes |
| `cleanup` | removing temporary artifacts the agent created | yes |

File tools (read, write, edit) require a reason; the harness assigns them a fixed type (`collect-info` for reads,
`change-state` for writes and edits). `uv run python epistemic_agent.py --types` prints the vocabulary as the model
sees it.

## Repository structure

| Path | Content |
|---|---|
| `epistemic_agent.py` | The harness: typed tools, declaration checks, journal and report, run metadata. Built on [agentknit](https://github.com/monperrus/agentknit). |
| `workspace_effects.py` | Effect capture: hashes the workspace before and after each call and records created, modified and deleted files and their diffs. |
| `consistency.py` | Consistency checker: compares declared types with effects; also runs offline on a stored journal. |
| `bwrap_sandbox.py` | Optional Bubblewrap sandbox: no network, no home directory, only the workspace writable, time and memory limits per command. |
| `bench/` | Runner for Impossible-LiveCodeBench: dataset download (pinned), task workspaces, attempts, scoring, resumable batch runs. |
| `analysis/` | Analysis scripts for the experiments: labelling packet, rater agreement, tables and the numbers used in the paper. |
| `experiments/` | One folder per experiment with its protocol, run scripts and committed results (see [experiments/README.md](experiments/README.md)). |
| `tests/` | Unit tests (no network by default) and opt-in live tests. |
| `paper.tex`, `references.bib`, `e2-numbers.tex`, `IEEEcsmag.cls`, `sfmath.sty`, `upmath.sty` | The paper source and the IEEE Computer Society magazine template. They stay at the root because the paper is synchronised with Overleaf. `e2-numbers.tex` is generated by `analysis/`. |
| `pyproject.toml`, `uv.lock` | Python project and pinned dependencies. |
| `runs/` | Raw run outputs (not in git; created by the scripts). |

## Install

Requires Linux, Python 3.11 or later and [uv](https://docs.astral.sh/uv/). Bubblewrap (`bwrap`) is needed only for the
sandbox.

```bash
uv sync --all-groups
```

## Run the tests

```bash
uv run pytest -q
```

The live tests need a model endpoint and an API key and are skipped by default (`uv run pytest -m live`).

## Run the agent

Any OpenAI-compatible endpoint works. API keys are read from an environment variable (`OPENLLM_API_KEY`, or the one
named by `--key-env`) or from the system keyring, under the endpoint's hostname with username `api_key`.

```bash
uv run python epistemic_agent.py --workspace path/to/ws --out-dir path/to/run --endpoint https://openllm.scilifelab.se/api Qwen3-235B-A22B "<task>"
```

The harness writes the journal (`journal.jsonl`), a readable report (`RATIONALE.md`), the diffs and full outputs of
every call, and the run metadata (`run.json`) to `--out-dir`, outside the agent's workspace. A step-by-step example,
the output files and the checker options are described in [experiments/README.md](experiments/README.md).
